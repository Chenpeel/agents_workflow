# AGENTS README

> 本文档作为 AGENTS 工作流必读文档
>
> 需由 Agent 生成的 `[AGENTS|CLAUDE|...].md` 指引阅读本文档

## 1. 工作流触发与命名

当用户指定某任务 TARGET 时，在本目录下创建对应的 `{TARGET}_{DATE}_workflow/` 文件夹。

### 命名规范（强制）

- **TARGET**：任务名称，使用小写英文短横线（kebab-case），必须准确描述任务，禁止泛化命名
- **DATE**：任务创建日期，格式固定为 `YYYYMMDD`（如 `20260804`）
- **后缀**：固定为 `_workflow`

示例：`teleop-mode-manager_20260804_workflow/`

## 2. 文档结构

该 `{TARGET}_{DATE}_workflow/` 文件夹的完整结构如下：

```bash
{TARGET}_{DATE}_workflow/
├── plan.md              # 长期蓝本 —— 实施方案
├── responsibilities.md  # 长期蓝本 —— 职责与边界
├── current.md           # 当前事实 —— 现状与推进进度
├── research/            # 调研文档（可选）
├── workflow_result/     # 工作流成果文档（可选）
├── dialogue_context/    # 与 Agent 的对话记录（可选）
└── tmp/                 # 暂时性文档：测试结果、debug 记录等（可选）
```

> 三个 `.md` 文件为必建项；四个子目录按需创建，不存在时无需建立。

## 3. 文档定位与维护规则

### 长期蓝本（`plan.md` / `responsibilities.md`）

> 作为长期目标，不在推进中直接修改。
> 任何实现和提交，都要先回到这两份蓝本文档看"目标边界是什么"。

- **创建**：任务开始时一次性生成，此后默认冻结
- **修改**：仅当任务目标/边界发生变更时，先向用户说明改动点并等待授权，批准后方可修改
- **联动**：每次修改后，必须在 `current.md` 中记录该变更

### 当前事实（`current.md`）

> 当前实际落地情况与推进进度只写入以下一个文档。

- **更新时机**：每轮实现、提交后同步更新，不得拖延到任务结束
- **`current.md`**：记录当前已落地 / 未落地的事实、相对 `plan.md` 的整体完成度（百分比 + 进度条），与阶段结论
- **边界**：只记录事实与进度，不得改动蓝本内容

## 4. 任务收尾（Definition of Done）

任务实现与验收全部完成后，按以下顺序收尾：

1. 将 `current.md` 中的完成度更新至 100%，并写明最终结论与遗留事项
2. 保留 `{TARGET}_{DATE}_workflow/` 文件夹作为该任务的完整档案，**不删除**
3. 按 `plan.md` 模板"文档"一节的要求，完成模块 `README.md` 编写

## 5. 参考

生成以上文档时，以 `./template_workflow/` 中的模板为骨架：

- 每个模板头部自带"文档定位 / 读者 / 更新规则 / 配套文档"自述，生成时不得删除
- 模板中各章节的斜体提示为填写指引，完成后可保留或删除
- 新建工作流文件夹时，直接复制 `template_workflow/` 下三个文件并替换占位符 `{TARGET}`、`{DATE}`
